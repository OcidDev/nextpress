# NextPress 0.2.1

Rilis perbaikan keamanan, impor/ekspor, siklus tema, dan verifikasi pemulihan data.

## Keamanan

- Login mengirim kredensial melalui POST, termasuk sebelum JavaScript siap atau
  saat JavaScript dimatikan. Form native tetap memakai CSRF/rate limit Better Auth.
- Hilangkan password/email bawaan, argumen password CLI, dan output password dari
  skrip reset admin. Reset mencabut sesi tanpa mengubah peran/status akun.
- Tolak pengubahan akun yang lebih berkuasa oleh peran kustom pengelola pengguna.
- Batasi percobaan password profil secara atomik dan cegah penimpaan kredensial
  yang berubah selama permintaan berlangsung.
- Gunakan satu header IP terpercaya untuk autentikasi, komentar, dan views.
- Perketat referrer admin/auth dan penyaringan secret/artefak dalam paket rilis.

## Tema dan pemisahan data

- Identitas, menu, footer, sosial, dan pengaturan beranda dapat diedit langsung
  di Sesuaikan tema dengan formulir dan penyimpanan CMS yang sama.

- Setiap tema menyediakan akses pengaturan situs; paket dapat mendeklarasikan
  kontrol desain dan panel susunan melalui `customizer.json` dan `layout.json`.
- Rancangan, tampilan aktif, dan pemulihan disimpan per tema. Pratinjau tema
  nonaktif tetap privat; tab dengan revisi, paket, atau tema aktif usang ditolak.
- Identitas, menu, footer situs, sosial, dan pilihan halaman beranda tetap milik
  CMS. Widget plugin hanya menyimpan referensi; plugin tetap dipasang terpisah.
- Tema nonaktif dapat dihapus, termasuk entri tema bawaan; cadangan internal tetap
  tersedia. Hapus menolak tema yang melayani situs atau dipakai template halaman.
- Riwayat tampilan lama disalin sekali ke tema pemiliknya tanpa menghapus backup.
- Tes siklus tema dijalankan dalam CI dan workflow rilis. Paket tema/plugin
  eksternal tidak ditambahkan ke distribusi core.

## Pembaruan instalasi independen

- Tambahkan worker server/VPS: klik pembaruan di dashboard membuat antrean
  persisten; proses berlanjut di luar request web tanpa memerlukan `git pull`.
- Verifikasi sumber/ukuran/checksum arsip dan commit, tolak path berbahaya,
  buat backup, build di direktori terpisah, lalu tukar versi aktif dan restart.
- Periksa versi dan commit setelah restart. Kegagalan kesehatan mencoba
  mengembalikan kode lama; interupsi meninggalkan journal untuk recovery operator.
- Versi awal worker menolak perubahan schema, perubahan source lokal, dan
  instalasi yang belum disiapkan sesuai panduan server/VPS.
- Adapter Vercel memakai repository penerbit rilis, bukan ID clone pengguna.
  Akses lintas repository masih perlu diuji pada akun Vercel tujuan.
- Tambahkan tes kegagalan updater, antrean PostgreSQL, proses instalasi/restart
  sungguhan pada fixture, dan alur pembaruan di browser.

## Dependency produksi

- Perbarui Next.js beserta paket terkait ke 15.5.28, sanitize-html ke 2.18.1,
  Zod ke versi yang sudah ditambal, dan batasi deepmerge minimal 4.3.2.
- Audit produksi harus tetap lulus sebelum rilis; hasil audit merupakan kondisi
  saat pemeriksaan, bukan jaminan terhadap advisory yang terbit kemudian.

## Impor, ekspor, dan pemulihan

- Batas impor XML konsisten 4 MB pada UI dan server. Berkas terlalu besar ditolak
  di browser sebelum dikirim. Pecah ekspor yang lebih besar menjadi beberapa berkas.
- Batas 1.000 pos/laman WXR dan 2.000 pos/laman Blogger sekarang menghasilkan
  pesan galat; impor tidak lagi memotong daftar diam-diam.
- Impor WXR melewati tipe selain pos/laman, mempertahankan entity XML dan CDATA,
  serta ekspor menyertakan tag dan menangani karakter penutup CDATA dengan benar.
- Jelaskan bidang yang benar-benar didukung: impor WXR belum membawa komentar,
  media, bidang kustom, kategori, atau tag. Ekspor WXR bukan backup instalasi lengkap.
- Tambahkan tes browser alur editorial, media, impor/ekspor, tema, dan plugin;
  tes migrasi database berisi data, backup/restore, serta pemeriksaan hosting baca-saja.

## Open source

## Tindakan operator

1. Ganti password yang pernah muncul di URL atau pernah menggunakan fallback
   skrip reset lama. Membersihkan URL tidak menghapus salinan pada history/log.
2. Set `NEXTPRESS_CLIENT_IP_HEADER` sesuai header yang ditimpa proxy dengan satu
   IP terpercaya; default `x-real-ip`, Vercel `x-forwarded-for`. Tutup akses publik
   langsung ke port aplikasi di belakang proxy.
3. Backup database sebelum memperbarui. Jalankan `pnpm db:migrate`,
   `pnpm db:check`, lalu build dengan environment hosting tujuan.
4. Setelah deploy, jalankan `pnpm release:verify https://domain-anda.example`.

Tidak ada migrasi database baru dibanding 0.2.0. Pemulihan kode ke 0.2.0
mengembalikan masalah keamanan yang diperbaiki di sini, walaupun skemanya sama.
