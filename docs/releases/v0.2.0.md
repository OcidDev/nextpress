# NextPress 0.2.0

Rilis stabil pertama yang mendukung pembaruan dari dasbor.

## Yang baru

- **Hapus tema** dengan pemeriksaan ulang di server. Tema aktif, tema bawaan
  (`core-default`), dan tema yang dipakai template halaman ditolak dengan alasan
  yang bisa ditindaklanjuti.
- **Hapus plugin** memakai alur uninstall yang sudah ada; plugin harus nonaktif
  dan tidak lagi dirujuk widget, template halaman, draf, atau Sampah.
- **Pemisahan data inti dan tema.** Identitas situs, menu, footer, tautan sosial,
  dan pengaturan bacaan kini hidup di opsi `site`. Revisi tampilan hanya menyimpan
  chrome tema; draf/pemulihan tidak dapat menimpa pengaturan inti.
- **Halaman Dasbor → Pembaruan** membaca GitHub Release stabil terbaru, menampilkan
  versi terpasang, catatan rilis, dan status kompatibilitas, lalu memulai
  pembaruan lewat adapter deployment.
- **Adapter Vercel** memverifikasi versi lewat `GET /api/version` setelah deployment
  selesai; pekerjaan tercatat di tabel `update_jobs` dan indeks unik parsial
  menolak dua pekerjaan aktif.
- **Kontrak rilis GitHub**: workflow `.github/workflows/nextpress-release.yml`
  menghasilkan arsip deterministik dan `nextpress-release.json` di setiap tag.

## Perubahan yang perlu diperhatikan

- Cabang kapabilitas tema `appearance-editor` sudah dihapus. Semua tema dirender
  lewat `ThemePage`; `capabilities` pada manifest tema diabaikan.
- Alias ID tema `twentytwentyfour` tetap dipetakan ke `core-default` saat dibaca,
  tetapi paket baru dengan ID itu ditolak saat diunggah.
- Preview tema starter (`/preview/template/[name]`, `examples/themes/starter`)
  dan ekstensi contoh `example-reading-time` sudah dihapus.
- Registry runtime ekstensi server (`contentSeo`) bawaan kosong. Plugin yang
  mendeklarasikan ekstensi server tetap bisa dipasang, tetapi belum memberi
  perilaku sampai runtime-nya dikompilasi dan didaftarkan.
- `pnpm vercel-build` menerapkan migrasi dan pemeriksaan database hanya ketika
  `VERCEL_ENV=production`.

## Migrasi database

Database baru: jalankan `pnpm db:migrate`, lalu `pnpm db:check`.

Terdapat empat migrasi: `0000_stale_piledriver`, `0001_faulty_nehzno`,
`0002_theme_deletion_permission`, dan `0003_update_jobs`. Karena ini rilis
pertama, `rollbackSafe` bernilai `false`: mengembalikan kode ke versi sebelumnya
tidak otomatis membatalkan skema yang sudah diterapkan. Cadangkan database
sebelum memasang.

## Persyaratan

- Node.js 22 atau lebih baru
- pnpm 11.22.0
- PostgreSQL 16
